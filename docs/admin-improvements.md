# Обновление админки Dahar

Все страницы показывают скелетоны при первой загрузке, ошибку с повтором при сбое и уже загруженные данные во время обновления. Есть время последнего обновления и ручная кнопка. Автоматические обновления не идут в фоновой вкладке. При создании аккаунта с недоступным буфером обмена окно остаётся открытым с доступом для сохранения вручную. Модалки и переходы получили короткие анимации с поддержкой `prefers-reduced-motion`; уведомления раскрыты отдельно. Доступны светлая, тёмная и системная темы. Выход из админки доступен и на телефоне.

Добавленная информация и инструменты:

- **Обзор:** периоды графиков 7/30/90 дней, первые полезные действия, количество аккаунтов с 2FA, аккаунты без визитов, данные об уведомлениях, Web Push, резервных версиях и изменениях за неделю.
- **Пользователи:** серверный поиск с задержкой и отменой устаревшего запроса, фильтры активности, блокировки, Telegram и 2FA, сортировка и страницы по 50 аккаунтов. Фильтры сохраняются в URL. Статистика считается для пользователей текущей страницы.
- **Карточка пользователя:** события активации с датами, статус 2FA, напоминания и час дайджеста, подписки, резервные версии, ошибки за 30 дней, исчерпанные попытки доставки, даты истечения сессий. Содержимое пользовательских записей и секреты 2FA не раскрываются.
- **Ошибки:** поиск по сообщению или логину, источник, календарный период в часовом поясе сервера, группы частых ошибок, затронутые пользователи и пагинация. График и счётчики используют одинаковый фильтр. Очистка всего журнала требует подтверждения и записывается в аудит.
- **Журнал действий:** поиск по пользователю, администратору или техническому названию действия, фильтр действия, пагинация и раскрытие деталей.
- **Система:** поиск таблиц, ограниченная высота таблицы и закреплённые заголовки, размеры индексов, оценки мёртвых строк и время анализа. Диагностика соединений приложения и PostgreSQL, кэша, откатов и взаимных блокировок. Фоновый цикл в процессе `web` обозначен как отдельный worker, его здоровье здесь не измеряется.
- **CSV:** экспорт текущей страницы пользователей, ошибок и аудита с UTF-8 BOM, экранированием кавычек и защитой от формул. Это экспорт страницы, а не всего набора по фильтру.

Оптимизация и надёжность:

- Страницы и графики загружаются отдельными JS-частями. Основной файл админки уменьшился примерно с 848 до 305 КБ без сжатия; графики остаются отдельной частью около 378 КБ и загружаются там, где используются.
- Подключённые направления агрегируются в PostgreSQL; клиент не получает настройки каждого аккаунта. Подсчёт записей и дневных значений выполняет агрегацию и применяет фильтры внутри каждой таблицы.
- Миграция `007_admin_reporting_indexes` добавляет индексы для сортировки пользователей, фильтрации ошибок и аудита и подсчёта записей по времени. Она применяется штатным механизмом при старте сервера. Создание индексов на больших таблицах может увеличить время миграции и временно задержать записи.
- Существующие массивные ответы `/users` и `/audit` сохранены для совместимости; интерфейс использует режим `paged=1` с ограничением страницы до 100 строк.
- Изменение имени, пароля, блокировки, завершение соответствующих сессий и аудит фиксируются одной транзакцией. Все поля проверяются до записи. Некорректный ID возвращает 404. Ответы API админки имеют `Cache-Control: no-store`.
- Прошедшие недели без визитов в удержании показывают 0%; будущие — прочерк. Текущая неделя отмечена как незавершённая.

Проверки: `npm run check`, `npm run build`, `npm test -w server`, `npx playwright test`. Новые серверные проверки покрывают границы страниц, поиск литералов, одинаковые фильтры ошибок и графика, валидацию без частичной записи, приватность диагностики и различие между нулевым и неизвестным удержанием. Браузерный сценарий проверяет медленную загрузку, повтор после ошибки, сохранение данных при сбое обновления, переходы между страницами пользователей, CSV, редактирование аккаунта, аудит, диагностику и темы.
