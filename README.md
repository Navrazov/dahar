# Dahar

«Дахар» по-чеченски — «жизнь». Это личный сервис, в котором собрана жизнь целиком: задачи, проекты, календарь, цели, привычки, деньги. Плюс направления, которые включаются по желанию: партнёры, трейдинг, небольшой бизнес. Есть Telegram-бот для быстрого ввода, на телефон ставится как приложение.

Аккаунты выдаёт владелец, у каждого пользователя свои данные. Для владельца есть отдельная админка.

## Что внутри

```
shared/   общая схема данных: из неё сервер строит таблицы и проверяет записи, клиент берёт типы
server/   API на Express и Postgres (TypeScript), Telegram-бот, push, фоновые задачи
client/   приложение для пользователей, React + Vite, работает и без сети
admin/    админка владельца, отдельное React-приложение
e2e/      сквозные тесты на Playwright
```

Сервер отдаёт оба фронтенда: приложение по адресу `/`, админку по `/admin`.

## Запуск на своём компьютере

Нужны Node.js 24+ (сервер на TypeScript запускается напрямую, без сборки) и PostgreSQL (на маке проще всего Postgres.app).

```bash
createdb dahar
npm install
npm run user -- create tim 'пароль-от-8-символов' "Тимур"
npm run admin -- create Owner 'пароль-администратора'
npm run dev
```

После этого:

- приложение — http://localhost:5173
- админка — http://localhost:5174/admin/
- API — http://localhost:3001

Таблицы создаются сами при старте сервера. Другую базу можно указать через `DATABASE_URL`.

## Пользователи

Открытой регистрации нет. Завести человека можно в админке («Пользователи» → «Пользователь») или из терминала:

```bash
npm run user -- create <логин> <пароль> "Имя"
npm run user -- password <логин> <новый-пароль>   # заодно завершает его сессии
npm run user -- list
npm run user -- delete <логин>                    # удаляет человека со всеми данными
```

## Админка

Учётные записи администраторов лежат в отдельной таблице и никак не связаны с пользователями: войти в админку пользовательским паролем нельзя, и наоборот. Кука админки живёт только на `/api/admin`.

Что там есть:

- **Обзор** — сколько людей, кто заходил сегодня, за неделю и за месяц, регистрации, сколько записей заводят, какие направления подключают, размер базы и файлов.
- **Пользователи** — список с поиском и фильтрами («активны за неделю», «пропали на месяц»). На странице человека — когда заходил, сколько записей и в каких разделах, с каких устройств открыты сессии. Можно переименовать, сбросить пароль, разлогинить везде, заблокировать, удалить.
- **Активность** — удержание по неделям: какая доля зарегистрировавшихся возвращается через неделю, две и дальше.
- **Ошибки** — падения сервера и ошибки в браузерах пользователей за 30 дней, со стеком.
- **Система** — версия, аптайм, память, размеры таблиц, миграции, состояние бота и фоновых задач. Здесь же смена пароля администратора.
- **Журнал действий** — что и когда делалось в админке.

Содержимое записей (тексты задач, суммы, имена клиентов) админка не показывает, только количества.

Вход в админку всегда со вторым фактором: при первом входе нужно отсканировать QR-код в приложении-аутентификаторе (Google Authenticator, 1Password, Яндекс Ключ), дальше каждый вход — пароль и шестизначный код.

Управление администраторами из терминала:

```bash
npm run admin -- create <логин> <пароль>
npm run admin -- password <логин> <новый-пароль>
npm run admin -- list
npm run admin -- delete <логин>
npm run admin -- reset-2fa <логин>   # потерян телефон: привязать приложение заново
```

## Безопасность

- Пароли — scrypt; в базе только хеш токена сессии; куки `HttpOnly`, `SameSite=Lax`, `Secure` в проде.
- Двухфакторная защита для пользователей по желанию (**Настройки → Двухфакторная защита**) с десятью одноразовыми кодами восстановления; для админки — обязательно. Потерян телефон и коды: `npm run user -- reset-2fa <логин>`.
- Перебор паролей ограничен и по адресу, и по логину; ответ на несуществующий логин приходит так же долго, как на неверный пароль.
- Каждая запись проверяется по общей схеме: допустимые значения статусов, длина текстов, формат дат, диапазоны чисел. Тело запроса — до 1 МБ (до 25 МБ только для файлов, выписок и восстановления).
- Строгая Content-Security-Policy без inline-скриптов, HSTS, запрет встраивания в iframe.

## Поиск, офлайн и уведомления

- **⌘K / Ctrl+K** (или **/**) открывает поиск по всем записям и командам: найти задачу, партнёра, операцию, создать запись, перейти в раздел. **N** в любом месте создаёт задачу.
- **Без сети** приложение открывается из кэша на устройстве и показывает последние данные. Изменения сохраняются в очередь и уходят на сервер, когда связь вернётся; вверху видно, сколько изменений ждут отправки. При выходе из аккаунта всё сохранённое на устройстве стирается.
- **Push-уведомления** (**Настройки → Уведомления в браузере**): напоминания о задачах с кнопкой «Готово» и утренняя сводка — без Telegram. Ключи VAPID сервер создаёт сам и хранит в базе. На iPhone работает, если Dahar добавлен на экран «Домой».
- **Разбор недели** на странице «Итоги недели»: Claude смотрит на задачи, привычки, деньги и проекты и пишет, что получилось, что просело и что сделать дальше. Включается переменной `ANTHROPIC_API_KEY`; данные недели отправляются в Anthropic только по кнопке.

## Деплой на Railway

1. Залейте репозиторий на GitHub.
2. В Railway: **New Project → Deploy from GitHub repo**.
3. В том же проекте: **New → Database → PostgreSQL**.
4. В сервисе приложения, вкладка **Variables**:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `NODE_ENV` = `production`
   - `ADMIN_LOGIN` и `ADMIN_PASSWORD` — администратор появится при первом запуске
5. **Settings → Networking → Generate Domain**.

Сборка и запуск описаны в `railway.json`, проверка здоровья — `/api/health`.

Бот, напоминания и сводки работают ровно в одном экземпляре: экземпляры договариваются через блокировку Postgres, и если ведущий упал, задачи подхватывает другой. Поэтому веб можно запускать в нескольких копиях. Для разделения задайте `ROLE`:

- `ROLE=web` — только HTTP (масштабируйте сколько нужно);
- `ROLE=worker` — только бот и фоновые задачи (отдельный сервис, команда `npm run worker`);
- без `ROLE` — всё вместе, как раньше.

По SIGTERM сервер дожидается текущих запросов и отпускает блокировку, так что деплой не обрывает работу. Лимиты попыток входа хранятся в памяти каждого экземпляра.

`ADMIN_PASSWORD` используется только при первом создании администратора. Потом пароль меняется в админке, и переменную можно удалить.

Пользователей на сервере удобнее заводить из админки. Если нужен терминал, укажите публичный адрес базы (Postgres → Variables → `DATABASE_PUBLIC_URL`):

```bash
DATABASE_URL="<DATABASE_PUBLIC_URL>" npm run user -- create <логин> <пароль> "Имя"
```

Если база требует TLS, добавьте `PGSSL=true`.

## Переменные окружения

| Переменная                                                                          | Зачем                                                                        |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `DATABASE_URL`                                                                      | Postgres. Локально по умолчанию `postgres://localhost:5432/dahar`            |
| `NODE_ENV=production`                                                               | Куки с флагом `Secure`                                                       |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD`                                                     | Создать администратора при первом запуске                                    |
| `TELEGRAM_BOT_TOKEN`                                                                | Включает бота, напоминания и утреннюю сводку                                 |
| `PUBLIC_URL`                                                                        | Адрес сервиса для кнопки мини-приложения в боте. На Railway берётся сам      |
| `STT_API_KEY`, `STT_BASE_URL`, `STT_MODEL`                                          | Расшифровка голосовых в боте. По умолчанию Groq Whisper, подойдёт и OpenAI   |
| `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Хранить скриншоты в S3 или Cloudflare R2, а не в базе                        |
| `SENTRY_DSN`                                                                        | Ошибки сервера в Sentry                                                      |
| `VITE_SENTRY_DSN`                                                                   | Ошибки браузера в Sentry, задаётся при сборке                                |
| `DEFAULT_TZ`                                                                        | Часовой пояс, пока пользователь не выбрал свой. По умолчанию `Europe/Moscow` |
| `PGSSL=true`                                                                        | Принудительный TLS к базе                                                    |
| `ROLE`                                                                              | `web`, `worker` или пусто (всё вместе), см. «Деплой»                         |
| `ANTHROPIC_API_KEY`                                                                 | Включает разбор недели от Claude                                             |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`                            | Свои ключи для push. Без них сервер создаст ключи сам                        |

Ошибки в любом случае пишутся в лог одной JSON-строкой и попадают в раздел «Ошибки» админки. Sentry не обязателен.

## Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Добавьте `TELEGRAM_BOT_TOKEN` и перезапустите сервис.
3. В приложении: **Настройки → Telegram → Привязать**.

Боту можно писать как человеку: `купить молоко завтра в 15:00`, `расход 500 кафе`, `доход 120к зарплата`. Команды `сегодня`, `привычки` и `неделя` показывают списки с кнопками. Напоминания приходят во время задачи, сводка — утром в выбранный час.

## Выписки из банка

В **Финансах** есть кнопка «Загрузить выписку»:

- **Т-Банк** — CSV: счёт или карта → «Выписка» → период → формат CSV.
- **Сбер** — PDF: карта → «Выписки и справки» → «Выписка по счёту».
- **Любой другой банк** — CSV, в котором есть колонки «Дата», «Сумма» (или «Приход» и «Расход») и «Описание». Колонки узнаются по названиям, так читаются выгрузки Альфы, ВТБ и большинства банков.

Перед сохранением показывается список операций, категорию можно поправить. Исправленная категория запоминается для этого магазина и в следующий раз подставится сама. Одну и ту же выписку можно загружать повторно: уже загруженные операции не задвоятся. Если перевод с одной своей карты на другую есть в выписках обоих банков, он сохранится одним переводом между счетами, а не расходом и доходом.

Выписку можно просто **переслать Telegram-боту**. Он запишет её в счёт с названием банка (или в счёт, названный в подписи к файлу, или в основной) и ответит, сколько операций добавлено.

Разбор выписок лежит в `server/src/modules/finance/import/`: новый банк — новый файл рядом с `tbank.ts`, `sber.ts` и `generic.ts`.

## Резервные копии

- В Railway включите бэкапы базы (Postgres → **Backups**).
- Каждый пользователь может скачать свои данные: **Настройки → Данные**. Это JSON вместе со скриншотами, восстанавливается в любой аккаунт.

## Тесты и проверки

```bash
createdb dahar_test && createdb dahar_e2e_test
npm test            # сервер (node:test на настоящем Postgres) и клиент (Vitest)
npm run test:e2e    # сборка и сквозные сценарии в Chromium, включая мобильный экран
npm run check       # Prettier, ESLint, TypeScript во всех пакетах, линтер Feature-Sliced Design
```

Тесты стирают базу, поэтому запускаются только на базах с именем `*_test`. Сервер: никто не видит и не меняет чужие данные (по каждой таблице), валидация, вход и двухфакторная защита, админка, склад, точность денег, повторяющиеся задачи, напоминания и push, бот и выписки, миграции, выбор ведущего экземпляра. Клиент: статистика привычек, трейдинга, бизнеса, прогресс проектов и то, что списки значений в формах совпадают со схемой. E2E: вход, задачи, повторы, привычки, импорт выписки, поиск, офлайн, двухфакторная защита, вход в админку.

GitHub Actions (`.github/workflows/ci.yml`) прогоняет всё это на каждый push и pull request.

## Как устроен код

### Сервер

```
server/src/
  index.ts          запуск: миграции, HTTP и/или фоновые задачи (по ROLE), корректная остановка
  app.ts            сборка Express: порядок middleware и роутов
  config.ts         все переменные окружения в одном месте
  db/               пул, синхронизация схемы, миграции, кодек записей
  http/             заголовки безопасности, лимиты тела запроса, раздача фронтендов
  lib/              время, повторы задач, пароли, TOTP, куки, лимиты
  modules/          по модулю на область: routes → service → repository
    auth/  users/  settings/  records/  habits/  finance/  search/  push/  insights/
    files/  backup/  telegram/  monitoring/  admin/
  jobs/             напоминания, утренняя сводка, планировщик, выбор ведущего экземпляра
  cli/              команды npm run user и npm run admin
```

Сервер написан на TypeScript и запускается Node напрямую (type stripping), типы проверяет `npm run typecheck`.

Роуты только разбирают запрос и отвечают. Правила (склад, повторы задач, проверка, что ссылки ведут на свои записи) живут в сервисах, SQL — в репозиториях.

Новое поле или таблица — одна строка в `shared/src/schema.ts`: сервер добавит колонку при старте и начнёт проверять значения, у клиента появится поле в типах. Переименования, удаления, смена типа и перенос данных — новая миграция в конец `server/src/db/migrations.ts`.

### Фронтенд

Оба приложения разложены по [Feature-Sliced Design](https://feature-sliced.design/ru/):

```
src/
  app/        точка входа, роутер, провайдеры, стили
  pages/      страницы
  widgets/    крупные блоки: каркас с меню, списки задач, целей, событий
  features/   действия пользователя: вход, редактор записей, отметка привычки
  entities/   предметная область: задачи, проекты, цели, привычки, деньги
  shared/     API-клиент, утилиты, UI-кит
```

Слой может импортировать только из слоёв ниже и только через `index.ts` слайса.

Пара мест, которые пригодятся первыми:

- `client/src/features/edit-record/config/forms.ts` — поля формы для каждой сущности. Один редактор открывается отовсюду: `edit('tasks', { project_id })`.
- `client/src/entities/module/model/catalog.ts` — каталог направлений.
- `client/src/app/styles/index.css` — цвета и шрифт для светлой и тёмной темы.

Клавиша **N** в любом месте создаёт задачу, **⌘K** открывает поиск.
